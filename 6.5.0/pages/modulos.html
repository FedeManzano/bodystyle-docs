📦 Módulos

Bodystyle está compuesto por un conjunto de módulos codificados en JS, lo cual permite darle dinamismo y funcionalidad a los diferentes componentes expuestos a lo largo de esta documentación.
La intención de esta sección es permitirle al usuario comprender la estructura interna de la biblioteca y que aprenda cómo instanciar los diferentes módulos de la manera más eficiente posible.

Introducción

Bodystyle está diseñado para inicializar cada uno de los módulos que la componen a través de su OBJETO GLOBAL llamado BS. Este objeto permite el acceso a los métodos dispuestos que permitirán no solo inicializar los módulos, sino también destruirlos en caso de necesidad para optimizar recursos.
Si bien la opción anteriormente descripta es la más utilizada, también podemos inicializar los módulos de manera individual, y utilizar las funciones de inicialización y destrucción de cada módulo por separado.

Webpack

Para modularizar todos los módulos que integran a Bodystyle se utilizó Webpack, un empaquetador de módulos estático para aplicaciones JavaScript modernas. Cuando Webpack procesa la aplicación, internamente construye un gráfico de dependencias. Es necesario conocer como funciona para poder aprovechar al máximo la biblioteca.
Cada módulo de Bodystyle está contenido en la carpeta /src/modulos/ y cada uno de ellos exporta una clase que contiene los métodos necesarios para inicializar y destruir el módulo.
Al momento de compilar la biblioteca, Webpack toma cada uno de estos módulos y los combina en un solo archivo de salida, que es el que se utiliza en producción. Esto permite que Bodystyle sea fácilmente integrable en cualquier proyecto web, ya que solo se necesita incluir un único archivo JS en lugar de múltiples archivos. 

    // Permite obtener el path absoluto desde donde se esté trabajando
    const path = require('path');

    module.exports = {

      // Archivo de entrada
      // Es necesario definirlo para que Webpack sepa dónde comenzar a construir el gráfico de dependencias
      entry: './src/app.js',

      output: {
        // Nombre del archivo de salida 
        // Dependiendo en que estapa del desarrollo estemos, este archivo puede ser minificado o no
        // En este caso, se está generando el archivo minificado
        filename: 'bodystyle.min.js',

        // Carpeta de salida /dist/js/
        path: path.join(__dirname, 'dist/js'),
      },
      resolve: {
        // Extensiones que se van a utilizar
        extensions: ['.js', '.ts', '.css']
      },
      module: {
        // Reglas para los loaders
        rules: [
          { test: /\.js$/, exclude: /node_modules/, loader: "babel-loader" },
          { test: /\.css$/i, use: ["style-loader", "css-loader"] },
        ]
      },
      // Modo de compilación (producción en este caso)
      mode: "production"
    };

    npm run build // Comando para ejecutar la compilación con Webpack

 Información

Con este último comando, Webpack tomará el archivo de entrada definido en la configuración, analizará todas las dependencias y generará el archivo de salida en la carpeta especificada

Inicializar Módulos

Como se mencionó existen dos formas de inicializar los diferentes módulos de la biblioteca: Una de ellas es a través del OBJETO GLOBAL BS, y la otra es inicializando cada módulo por separado. 

    // El código que está debajo es posible si tenemos agregado a nuestro proyecto 
    // el archivo bodystyle.min.js que permitirá el acceso al objeto BS
    // BS es el objeto global de Bodystyle
    BS.ToolTipsInit(); // Inicializa el módulo ToolTips
    BS.BotonInicioInit(); // Inicializa el módulo Botón Inicio
    BS.CodigoHtmlInit(); // Inicializa el módulo Código HTML

 Información

Cada módulo de Bodystyle tiene su propio método de inicialización y destrucción. Es importante consultar la documentación específica de cada módulo para conocer los detalles de su uso.

La otra forma de inicializar los módulos es importándolos directamente en nuestro proyecto y utilizando sus métodos de inicialización y destrucción.

Estados

Cada módulo de Bodystyle puede encontrarse en dos estados: Inicializado o Destruido. Cuando un módulo está inicializado, significa que sus funcionalidades están activas y disponibles para su uso en la página web. Por otro lado, cuando un módulo está destruido, sus funcionalidades son desactivadas y los recursos asociados son liberados.
Es importante gestionar adecuadamente el estado de los módulos para optimizar el rendimiento de la página web y evitar conflictos entre diferentes módulos.
La inicialización y destrucción de los módulos se realiza a través de los métodos proporcionados por cada módulo o mediante el objeto global BS. 

    BS.ToolTipsInit(); // Inicializa el módulo ToolTips
    // ... uso del módulo ToolTips ...
    BS.ToolTipsDestroy(); // Destruye el módulo ToolTips

    /**
       Los eventos asociados al elemento se desvinculan y los recursos son liberados.
    */

 Angular

Para ejempleficar lo anterior se toma el framework Angular, en donde cada componente tiene un ciclo de vida bien definido. Al inicializar un módulo de Bodystyle dentro de un componente, es recomendable inicializarlo en el método ngOnInit() y destruirlo cuando el/los elementos no se utilicen, veamos un ejemplo: 

    class MiComponente implements OnInit, OnDestroy {
        ngOnInit() {
            // Inicializar el módulo ToolTips cuando el componente se inicializa
            BS.ToolTipsInit();
        }

        /**
            Esto puede hacerse en cualquier momento no necesariamente 
            en este método.
        */
        ngOnDestroy() {
            // Destruir el módulo ToolTips cuando el componente se destruye
            BS.ToolTipsDestroy();
        }
    }

    /** 
        De esta manera, nos aseguramos de que el módulo ToolTips esté activo 
        solo mientras el componente esté en uso, optimizando así el rendimiento 
        y evitando posibles conflictos. Bodystyle hace uso de los recursos 
        de manera eficiente, permitiendo una mejor experiencia de usuario.
    */
